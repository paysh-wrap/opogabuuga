# Trading-R1 headless embedding spike
- trading-r1 0.1.1 (latest; 0.1.0 also exists), Apache-2.0, py>=3.12. uv venv --python 3.12; `uv pip install trading-r1==0.1.1` -> 68 pkgs (69 listed incl. itself), 403 MB venv, ~80 s. Pulls numpy, scipy, reportlab, pdfplumber, anthropic, openai, google-genai, fastapi, uvicorn, trafilatura, ddgs.
- CLI `trading-r1 [question] [--mode auto|research|analytical] [--profile tauric|gpt|anthropic|gemini|vllm|ollama]` = TUI launcher; REQUIRES bun (terminal.py: "the terminal needs `bun`") and runs `bun install` on first use. There is NO non-TUI one-shot/JSON CLI command. Subcommands: serve export jobs channels secrets daemon sync sessions.
- Headless path that works: `trading-r1 serve` (FastAPI, 127.0.0.1 only, bun NOT needed). POST /research {"question","mode","profile","stream":false,"session_id"} -> sync JSON trajectory {question,text,termination,error,rounds,messages,...}. Auth: Bearer token published in $TR1_HOME/backend.json (0600), or TR1_API_AUTH=off, or TR1_API_TOKEN env. Single backend per TR1_HOME via flock (backend.lock). TR1_PORT sets port. Tested: with TR1_HOME redirected, serve started, /research profile=anthropic reached api.anthropic.com (401, no valid key) and returned JSON error. No "answer JSON schema" option: structured output must be requested in the prompt (like TA_SETUP line) and parsed from `text`.
- No stable python import API documented; internal modules (trading_r1.runtime.agent etc.) importable but undocumented/unstable. HTTP /research is the sensible interface. export: `trading-r1 export SESSION --format md|html|pdf -o file` (needs running backend).
- Keys: env ANTHROPIC_API_KEY / OPENAI_API_KEY / GEMINI_API_KEY / TAURIC_API_KEY, or TR1_VLLM_BASE_URL; stored alternative `trading-r1 secrets set` -> $TR1_HOME/credentials.json (plaintext, 0600). Env wins over store. Use env only.
- Config redirect: TR1_HOME moves ALL state (settings, credentials, sessions, sqlite, lock, logs); also TR1_REPORTS_DIR, TR1_LOG_FILE, TR1_SKILLS_DIR, TR1_<NAME>_MODEL/BASE_URL. Nothing written to real HOME in my test.
- Hosts seen in code: api.anthropic.com, api.openai.com, generativelanguage.googleapis.com, api.tauric.ai (tauric profile AND sync client default base; data tools use TAURIC key), api.telegram.org (channels, opt-in), plus arbitrary web (ddgs search + trafilatura page fetch) in auto/research mode. No explicit telemetry found; `sync` (session upload to Tauric account) exists and service/syncing.py is wired in -> keep unconfigured / verify no tauric key => no sync. Analytical mode is "numbers-first" (tools); data tools likely need TAURIC_API_KEY for market data (untested, no key).
- Existing pattern (ta_runner.py = stdin/stdout JSON inside .venv-ta; ensure_ai_tools() in desktop/paytience_app.py builds venvs under paytience-data via uv/venv, pip install pinned): Trading-R1 fits as .venv-tr1 with `pip install trading-r1==0.1.1`, but needs a small runner that spawns `trading-r1 serve` (TR1_HOME=paytience-data/tr1, TR1_API_AUTH=off or read token, loopback port), POSTs /research, parses JSON, kills the server. Not a plain subprocess one-shot.
- Blockers/risks: no JSON one-shot CLI (need serve+HTTP wrapper); 400 MB install; Python 3.12 (same as TA, fine); no GPU needed for hosted profiles; v0.1.x immature, large unaudited agent with web-browsing tools (prompt-injection from fetched pages -> treat output as advisory, validate numbers as with TA_SETUP); cost/token usage unbounded unless runtime.json limits set; daemon/channels/sync features must stay unused; LLM answers non-deterministic and unbacktestable.
